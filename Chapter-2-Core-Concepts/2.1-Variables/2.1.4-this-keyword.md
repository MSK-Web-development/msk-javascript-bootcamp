# "this" keyword

## 🔑 Key Concept: Execution Context

Unlike many other programming languages where `this` always refers to the instance of the class, in JavaScript, the value of `this` is **determined dynamically** by _how_ a function is called, not _where_ it's defined.

---

## 🧭 How `this` is Determined (Binding Rules)

The value of `this` is set according to four primary rules:

### 1\. Default (Global) Binding

When a function is called as a standalone function outside of any object or context (and not in **strict mode**), `this` defaults to the **global object** (e.g., `window` in a browser or `global` in Node.js).

- **Example (Non-Strict Mode):**

  ```javascript
  function showThis() {
    console.log(this); // Logs the global object (e.g., Window)
  }
  showThis();
  ```

- **Example (Strict Mode):**
  In strict mode (`"use strict"`), if `this` is not set by the call, it defaults to `undefined`.

  ```javascript
  "use strict";
  function showThisStrict() {
    console.log(this); // Logs undefined
  }
  showThisStrict();
  ```

### 2\. Implicit Binding

This is the most common scenario. When a function is called as a **method** of an object, `this` refers to the **parent object** that contains the method.

- **Example:**

  ```javascript
  const user = {
    name: "Alice",
    greet: function () {
      console.log(`Hello, my name is ${this.name}`); // 'this' refers to the 'user' object
    },
  };

  user.greet(); // Output: Hello, my name is Alice
  ```

### 3\. Explicit Binding

You can explicitly force a function to use a specific object as its `this` context using the built-in methods: `call()`, `apply()`, and `bind()`.

- **`call()` and `apply()`:** Execute the function immediately with the specified `this` value.

  ```javascript
  function logName() {
    console.log(this.name);
  }
  const person = { name: "Bob" };

  logName.call(person); // Output: Bob (Explicitly sets 'this' to 'person')
  ```

- **`bind()`:** Returns a **new function** permanently bound to the specified `this` value, which can be executed later.

### 4\. New Binding (Constructor Call)

When a function is invoked with the `new` keyword (a constructor function), the following happens:

1.  A brand new empty object is created.
2.  **`this` is bound to this new object.**
3.  The function body executes, typically adding properties to `this`.
4.  The new object is returned implicitly.

<!-- end list -->

- **Example:**
  ```javascript
  function Person(name) {
    this.name = name; // 'this' refers to the newly created object
  }
  const john = new Person("John");
  console.log(john.name); // Output: John
  ```

---

## 🏹 Special Case: Arrow Functions

**Arrow functions** (`() => {}`) handle `this` differently and are an important exception to the rules above.

- Arrow functions do **not** have their own `this` context.
- They inherit the `this` value from the **enclosing lexical scope** (the scope where they are defined, not where they are called). This is often called **Lexical Scoping**.

This behavior makes them ideal for callbacks, where you want to preserve the `this` context from the surrounding function or object.

- **Example:**

  ```javascript
  const handler = {
    id: 1,
    init: function () {
      // Traditional function (will lose 'this' context in setTimeout)
      setTimeout(function () {
        // 'this' would be the global object or undefined here
        // console.log(this.id); // Problem
      }, 100);

      // Arrow function (preserves 'this' from the 'init' method)
      setTimeout(() => {
        console.log(this.id); // 'this' correctly refers to the 'handler' object
      }, 100);
    },
  };

  handler.init(); // Output: 1
  ```

---

**In summary:** The value of `this` is not fixed in a traditional function; it changes based on the four binding rules of how that function is executed. Arrow functions, however, use **lexical scoping** to permanently inherit the `this` from their parent environment.
